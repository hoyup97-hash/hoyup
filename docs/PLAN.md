## 1. 목표와 독자

### 1.1 단일 목표

방문자가 **3분 안에 "이 사람을 면접에 부르자"** 는 판단에 도달하게 만든다. 그 외 목적은 없다.

### 1.2 독자 (단일 페르소나)

**채용담당자 · 헤드헌터 · 실무 면접관.** 타깃 직무는 ① 데이터 분석·전략기획 ② 영업·BD ③ 금융(자산운용·리서치·기업금융).

행동 전제:
1. **바쁘다** — 첫 화면 10초 안에 계속 읽을지 결정한다 → 히어로에서 수치가 바로 보여야 한다.
2. **검증한다** — 주장에는 숫자와 증거가 붙어야 한다 → 형용사 금지, 증거 이미지 필수.
3. **리스크를 본다** — 정치색·장기근속 우려는 즉시 탈락 사유다 → 4절 비노출 원칙을 절대 위반하지 않는다.
4. **연락 수단을 찾는다** — 어느 위치에서든 클릭 1회로 이메일·이력서에 닿아야 한다.

### 1.3 핵심 메시지

> ### "숫자로 판단하고, 현장에서 검증합니다."

모든 섹션·카피·디자인 결정은 이 문장을 강화하는 방향으로만 한다. 무관한 콘텐츠는 싣지 않는다.

### 1.4 성공 기준

- 히어로가 모바일에서 스크롤 없이 완결된다 (이름 + 메시지 + 수치 + CTA).
- 사이트 전체에서 정치 관련 단어 **0건** (`grep` 검증).
- 모든 화면 위치에서 이메일·이력서까지 클릭 1회.
- 형용사 성과 표현("크게", "많은", "성공적으로") **0건**.
- Lighthouse 성능·접근성·SEO 각 90점 이상.

## 2. 기술 스택과 파일 구조

### 2.1 스택

**정적 사이트(순수 HTML + CSS + 바닐라 JS), 빌드 도구 없음.** 외부 스크립트·라이브러리 0개. GitHub Pages 배포(`CNAME` = hoyup.kr).

```

│   ├── js/main.js          # 랜딩 렌더링·인터랙션
│   ├── js/case.js          # 케이스 페이지 공용 (카운트업·라이트박스)

├── docs/{PLAN,CAREER,EDIT_GUIDE}.md
├── robots.txt · sitemap.xml
└── (삭제) politics.html · projects/
```

### 2.3 확장성 원칙 ★

**케이스를 추가하는 작업이 "JSON 한 항목 + 페이지 파일 1개 복사"로 끝나야 한다.**

- `data/cases.json` 배열 순서 = 그리드 카드 순서. 항목 추가 = 카드 추가.
- 케이스 상세 페이지는 **모두 동일한 섹션 골격**을 쓴다(2.4절). 새 페이지는 기존 파일을 복사해 텍스트만 바꾼다.
- 케이스별 전용 CSS를 만들지 않는다. 모든 스타일은 `case.css`의 공용 클래스로 해결한다.
- 증거 이미지가 아직 없는 케이스는 **플레이스홀더 블록**을 그 자리에 남긴다(2.5절). 자료가 생기면 `<img>`로 교체.

### 2.4 케이스 상세 페이지 공용 골격

모든 `work/*/index.html`은 이 순서를 지킨다. 없는 블록은 통째로 생략하되 순서는 바꾸지 않는다.

| # | 블록 | 클래스 | 내용 |
|---|---|---|---|
| 1 | 얇은 헤더 | `.case-header` | ← 전체 보기 / 이름 / 이메일 버튼 |
| 2 | 히어로 | `.case-hero` | 아이브로우(기간·역할) → 문장형 헤드라인 → 한 줄 설명 |
| 3 | 수치 벨트 | `.metric-belt` | 카드 3~5장, 뷰포트 진입 시 카운트업 |
| 4 | 본문 | `.case-body` | 소제목 + 문단 + 증거 이미지. **CAREER.md의 스토리 아크 순서 그대로** |
| 5 | 전환점 | `.turning-point` | ★ 강조 블록 — "무엇이 틀렸고 어떻게 고쳤나". 배경 대비로 시각적 분리 |
| 6 | 배운 것 | `.takeaway` | 인용 형태 1~3문장 |
| 7 | 다음 케이스 | `.case-next` | 좌우 이동 링크 |
| 8 | 연락 CTA | `.contact` | 랜딩과 동일 컴포넌트 |

**전환점 블록(5)은 모든 케이스에 반드시 있다.** 이게 없으면 "나열"이지 케이스 스터디가 아니다(CAREER.md 1절).

### 2.5 미완성 콘텐츠 처리

자료가 없는 자리는 **비워두지 말고 명시적 플레이스홀더**를 둔다. 개발 중 무엇이 비었는지 한눈에 보이고, 배포 전 검색으로 잡아낼 수 있다.

- 증거 이미지 자리: `.evidence--empty` 박스 + `data-todo="자료명"` 속성
- 미확정 수치: `<span class="tbd" data-todo="...">—</span>`
- **배포 전 `grep -r 'data-todo' .` 로 잔여 항목을 전수 확인한다.**

## 3. 랜딩 페이지 구조 (index.html)

### 3.0 캐러셀 폐기 결정 (2026-07-31)

구 기획의 프로젝트 캐러셀을 **폐기한다.** 사유:
1. 자동 넘김은 채용담당자에게 **정보 은폐**다 — 슬라이드 4장 중 3장은 보지 않고 지나간다.
2. 케이스가 5개 이상으로 늘어날 예정이고(2.3절), 캐러셀은 개수가 늘수록 열람률이 떨어진다.
3. 첫 화면에서 "무엇을 만들었나"보다 **"이 사람이 누구고 숫자가 뭔가"** 가 먼저다.

→ **정적 히어로 + 케이스 그리드**로 대체한다.

### 3.1 고정 헤더

- 높이 56px, `position: fixed`, `--dark-bg` 85% 반투명 + `backdrop-filter: blur`.
- 좌: **이호엽**(h1, 클릭 시 최상단) · 옆: "숫자로 판단하고, 현장에서 검증합니다"(480px 이하 숨김)
- 우: `이력서` 고스트 버튼 + `이메일` 주 버튼
- z-index 최상위.

### 3.2 ① 히어로 (다크, 스크롤 없이 완결)

**목적**: 10초 안에 "누구 / 무엇을 하는 사람 / 근거 숫자 / 연락처"를 전달한다.

구성 (위→아래):
1. 아이브로우 — `DATA · STRATEGY · FIELD`
2. h1 — **숫자로 판단하고, 현장에서 검증합니다**
3. 리드 3문장 — 시장을 데이터로 읽고 → 도구를 직접 만들고 → 사람을 직접 만나 팔고 → 측정해서 고친다
4. **수치 벨트 4개** (tabular-nums, 카운트업)

   | 값 | 라벨 |
   |---|---|
   | 5배 | 메시지 교체 후 랜딩 유입 |
   | 10배 | 창업 월매출 성장 |
   | 1,866건 | 크롤링·구조화한 회의록 |
   | 50,000+ | 직접 만난 사람 |
5. CTA — `[이력서 PDF]` `[이메일 보내기]`

배경: `--dark-bg` 전폭. 우측 또는 배경에 절제된 그래픽 1개(과한 글로우 금지).

### 3.3 ② 케이스 그리드 ★ 사이트의 중심

**목적**: 커리어를 한 화면에 펼친다.

## 4. 정치 비노출 · 아카이브 처리 (절대 원칙)

CAREER.md 4절의 표현 규칙을 따른다. 추가로 코드 레벨에서:

## 5. 디자인 시스템

### 5.1 컬러 토큰 (2026-07-31 개정 — 액센트 교체)

**오렌지 `#FF6B00`을 폐기한다.** 두 가지 사유: ① 특정 정당의 상징색과 직결되어 정치 비노출 원칙과 충돌한다. ② 소비재·스타트업 톤이라 금융·데이터 트랙에서 오독된다.

**딥 페트롤(petrol blue)** 단일 액센트로 교체한다. 절제되고 신뢰감이 있으며, 흔한 코퍼레이트 네이비와도 구분된다.

```css
:root {
  --bg:           #FBFBF9;  /* 본문 배경 */
  --surface:      #FFFFFF;  /* 카드 */
  --band:         #F1F2EF;  /* 밴드 (케이스 그리드) */
  --ink:          #16161A;  /* 본문 텍스트 */
  --ink-sub:      #55565C;  /* 보조 텍스트 */
  --line:         #E2E3DE;  /* 구분선 */
  --accent:       #0E5163;  /* 액센트 — 주 버튼, 배지, 노드, 아이브로우 */
  --accent-dk:    #0A3F4D;  /* 호버 */
  --accent-text:  #0B4757;  /* 밝은 배경 위 본문 크기 링크 (4.5:1 확보) */
  --accent-tint:  #0E51631A;/* 배지 배경 (10% 틴트) */
  --dark-bg:      #0F1214;  /* 다크 섹션 (헤더·히어로·CTA) */
  --dark-surface: #191D20;  /* 다크 섹션 내 카드 */
  --dark-ink:     #FFFFFF;
  --dark-sub:     #B7BABF;
  --dark-accent:  #4FB3CC;  /* 다크 배경 위 액센트 (대비 확보용 밝은 톤) */
  --header-h:     56px;
}
```

> 액센트 교체는 **이 5개 변수만 바꾸면 전 페이지에 반영된다.** 톤이 마음에 들지 않으면 여기만 수정한다.

### 5.2 타이포그래피

Pretendard woff2 셀프호스팅(기존 유지). 스케일: h1 40/48px(모바일 30px), h2 28px, h3 20px, 본문 17px/1.7, 캡션 14px.
**수치는 48px 이상 + `font-variant-numeric: tabular-nums`.** 자간 한글 기준 -0.01em.

### 5.3 스타일 방향

- **섹션 배경 리듬**: 다크(헤더·히어로) → `--band`(케이스 그리드) → 밝은 배경(자기소개·타임라인) → `--band`(스킬) → 다크(연락 CTA)
- **섹션 헤더 패턴**: 중앙 정렬 타이틀 + 위에 액센트 아이브로우 라벨(`CASE STUDIES`, `TIMELINE`, `SKILLS`)
- **카드**: 라운드 16~20px, 은은한 그림자, 호버 시 2~4px 상승. 배지는 라운드 필.
- **수치 강조**: 사이트의 메시지가 "숫자로 판단한다"이므로 **숫자는 항상 본문보다 크고 액센트 색**이다. 이게 이 사이트의 시각적 시그니처다.
- **금지**: 회전·확대·긴 지속시간·반복 애니메이션, 이미지 속 텍스트, 외부 리소스.

### 5.4 모션

IntersectionObserver 기반 `.reveal` 유틸 하나로 전 페이지 통일(기존 구현 유지).
- 텍스트 리빌: 아래→위 12~16px + 페이드인 0.5초 ease-out, 형제 요소 60~100ms 스태거, 1회만.
- 숫자 카운트업: 뷰포트 진입 시 0→목표값 약 1.2초 ease-out. 접미사·단위 고정.
- `prefers-reduced-motion: reduce`에서 전부 끄고 최종 상태 즉시 표시. JS 꺼진 환경에서 콘텐츠가 숨겨지지 않아야 한다.
